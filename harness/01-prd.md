# 유저 스토리

출처: PRD 2장(유저 스토리), 3장(화면 구조의 "해결하는 유저 스토리").

| US | 누가 | 원하는 것 | 해결 화면 |
|---|---|---|---|
| US1 | 매달 20일쯤 데이터가 떨어지는 고객 | 20개가 넘는 요금제 중 내 사용 패턴에 맞는 후보만 좁혀 보고 싶다 | 요금제 목록 |
| US2 | "무제한" 요금제를 고르는 고객 | 기본 데이터를 다 쓴 뒤 속도가 제한되는 요금제인지 속도 제한이 없는 요금제인지 구분하고 싶다 | 요금제 목록, 요금제 상세 |
| US3 | 요금제를 고른 고객 | 매달 실제로 내는 돈과 24개월 프로모션이 끝난 뒤 금액을 알고 싶다 | 요금제 상세 |
| US4 | 신청을 망설이는 고객 | 이번 달 요금·위약금·유심 교체에 대한 안내를 확인한 뒤 매장에 가지 않고 그 자리에서 신청을 끝내고 싶다 | 변경 전 확인, 변경 신청 |
| US5 | 신청을 마친 고객 | 신청이 접수됐는지 그 자리에서 확인하고 싶다 | 신청 완료 (완료 직후 확인 범위까지) |

### 주요 흐름 (PRD 3장)

```
진입 → 요금제 목록 → 요금제 상세 → 변경 전 확인 → 변경 신청 → 신청 완료 → 끝
```

되돌아가는 흐름:
- 요금제 상세 → (뒤로) → 요금제 목록 (선택했던 필터 유지)
- 변경 전 확인 → (뒤로) → 요금제 상세
- 변경 신청 → (취소) → 요금제 상세 (입력값 삭제)
- 신청 완료 → (처음으로 / 뒤로) → 요금제 목록 (신청 화면으로 돌아가지 않음)

# 요금제 데이터

### PRD 4장 표 (원문 그대로)

실습용 가상 데이터 4개. 실제 통신사 요금제가 아니다.

| id | 이름 | 월 요금 (정가) | 매달 내는 돈 (24개월) | 데이터 | 소진 후 속도 | 유형 (type) | 추천 | 한 줄 설명 |
|---|---|---|---|---|---|---|---|---|
| p01 | 라이트 7 | 39,000원 | 32,000원 | 7GB | 400kbps | basic (기본형) | - | 영상보다 메신저·검색 위주로 쓰는 분께 맞는 요금제 |
| p02 | 출퇴근 50 | 55,000원 | 47,000원 | 50GB | 1Mbps | limited_unlimited (무제한 · 속도 제한 있음) | - | 출퇴근길에 짧은 영상을 매일 보는 분께 맞는 요금제 |
| p03 | 데일리 무제한 110 | 69,000원 | 59,000원 | 110GB | 5Mbps | limited_unlimited (무제한 · 속도 제한 있음) | ✓ | 출퇴근길 영상 시청이 길어 월말 전에 데이터가 떨어지는 분께 맞는 요금제 |
| p04 | 프리 무제한 | 89,000원 | 79,000원 | 제한 없음 | 제한 없음 | full_unlimited (완전 무제한) | - | 데이터 한도와 속도 제한 없이 쓰고 싶은 분께 맞는 요금제 |

- 24개월 할인 금액 = 정가 − 매달 내는 돈 (p01 7,000원 / p02 8,000원 / p03 10,000원 / p04 10,000원)
- 추천은 이번 범위에서 고정값이다(개인별 계산 없음).

### PRD 5장 필드 이름 (lib/plans.ts의 `export const PLANS`가 이 이름 그대로 써야 함)

```
Plan (요금제)                      # 4장 요금제 데이터. 이번 범위에서는 고정 데이터로 읽기만 함
  id                text           # p01 ~ p04
  name              text
  regular_price     integer        # 정가(원), 24개월 후 월 요금
  promo_price       integer        # 매달 내는 돈(원), 가입 후 24개월
  promo_months      integer        # 24
  data_gb           integer | null # null = 제한 없음
  speed_after       text | null    # 소진 후 속도, null = 제한 없음
  type              text           # type: basic / limited_unlimited / full_unlimited
  is_recommended    boolean        # true는 1개만
  description       text           # 한 줄 설명

Subscription (구독 신청)
  id                uuid
  application_no    text           # SUB-000000 형식, 중복 불가
  name              text           # 1~20자
  phone             text           # 숫자 11자리, 010으로 시작 (하이픈 없이 저장)
  plan_id           text           # 4장 요금제 데이터의 id
  privacy_agreed    boolean        # 항상 true (미동의 시 저장 불가)
  status            text           # status: received / processing / completed / canceled
                                   # 이번 범위에서는 received로만 생성
  created_at        timestamptz
```

# 화면별 문구

PRD 4장 원문 그대로. PRD에 없는 문구(screens.md에만 있는 것)는 따로 표시한다.

### 요금제 목록 (PRD 4-1)

| 구분 | 문구 |
|---|---|
| 제목 | "나에게 맞는 요금제 찾기" |
| 보조 문구 | "무제한 유형과 매달 내는 돈을 비교해 보세요." |
| 필터 칩 4개 | `전체` / `기본형` / `무제한 · 속도 제한 있음` / `완전 무제한` |
| 카드 유형 라벨 | `기본형` / `무제한 · 속도 제한 있음` / `완전 무제한` |
| 카드 금액 | 매달 내는 돈(`promo_price`), 보조 문구 "24개월 후 월 OO원"(`regular_price`) |
| 추천 배지 | "추천" (`is_recommended = true`인 카드 1개에만) |
| 안내 (빈 결과) | "이 유형의 요금제가 없어요." |
| 오류 (screens.md에만 있음) | `요금제를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.` |
| 개수 줄 (make-export 결정, PRD에 없음) | "매달 내는 돈 낮은 순 · N개" (N = 필터 결과 개수) |
| 카드 데이터 행 라벨 (make-export 결정, PRD에 없음) | "기본 데이터" / "소진 후 속도" |
| 카드 금액 라벨 (make-export 결정, PRD에 없음) | "매달 내는 돈" (금액 2개뿐 유지, PRD 3) |

동작·규칙
- 기본: `전체` 선택, 4개 전부, 매달 내는 돈 낮은 순(p01 → p02 → p03 → p04).
- 칩은 단일 선택. 탭하면 해당 `type` 카드만 남고 정렬 순서 유지.
- 카드 안 금액은 "매달 내는 돈"과 "24개월 후 월 요금" 2개만. 정가 취소선, 할인 금액, 할인율은 카드에 표시하지 않는다.
- 필터로 p03이 숨겨지면 추천 배지도 화면에서 사라진다.
- 카드 전체 영역 탭 → 해당 `id`로 요금제 상세.

### 요금제 상세 (PRD 4-2)

| 구분 | 문구 |
|---|---|
| 제목 | 요금제 이름(`name`) (PRD에 없음 → 확정 1) |
| 요금 요약 | 요금제 이름, 유형 라벨, 추천 배지(`is_recommended = true`일 때만), "매달 내는 돈" 금액, "가입 후 24개월 동안", "24개월 후 월 OO원" |
| 요금 구성 (3줄 고정) | `정가 월 OO원` / `24개월 할인 −OO원` / `매달 내는 돈 월 OO원` |
| 데이터 조건 — basic | "기본 데이터 {data}를 다 쓰면 이번 달 남은 기간 동안 최대 {speed_after}로 느려져요." |
| 데이터 조건 — limited_unlimited | "이름에 '무제한'이 있지만 기본 데이터 {data}를 다 쓰면 이번 달 남은 기간 동안 최대 {speed_after}로 느려져요." |
| 데이터 조건 — full_unlimited | "기본 데이터 한도와 속도 제한이 없어요." |
| 버튼 (하단 고정) | "이 요금제로 변경하기" (기본 활성) |
| 안내 (빈, screens.md에만 있음) | `요금제를 찾을 수 없어요.` |
| 오류 (screens.md에만 있음) | `요금제 정보를 불러오지 못했어요. 잠시 후 다시 시도해 주세요.` |
| 섹션 제목 (make-export 결정, PRD에 없음) | "요금 구성" / "데이터 조건" |
| 데이터 행 라벨 (make-export 결정, PRD에 없음) | "기본 데이터" / "소진 후 속도" (값은 PRD 표 표기, p04는 "제한 없음") — 그 아래 유형별 데이터 조건 문장(PRD 원문) |
| 하단 금액 줄 라벨 (make-export 결정, PRD에 없음) | "매달 내는 돈" + "월 OO원"(`promo_price`) + 버튼 "이 요금제로 변경하기" |

동작·규칙
- 할인 금액 = `regular_price − promo_price`.
- 금액 이름은 "정가", "24개월 할인", "매달 내는 돈" 3가지만. "할인가", "프로모션가"라는 단어는 쓰지 않는다.
- 변경 버튼 → 같은 `id`로 변경 전 확인.
- 뒤로 가기 → 요금제 목록, 이전 필터 칩 상태 유지.

| 요약 행 라벨 (make-export 결정, PRD에 없음) | "선택한 요금제" / "매달 내는 돈" / "24개월 후 월 요금" |

동작·규칙
- 3개 항목 모두 펼친 상태, 접기/펼치기 없음. 숫자 금액은 안내 항목에 표시하지 않는다.
- PRD 주석: 위 안내 문구는 초안이다. 실제 요금·위약금·유심 정책 확인 후 문구를 확정한다. → 확정 3: 이번 구현은 초안 문구 그대로 쓴다.
- "신청하기" → 같은 `id`로 변경 신청. "다른 요금제 보기" → 요금제 목록.
- 뒤로 → 요금제 상세.

### 변경 신청 (PRD 4-4)

| 구분 | 문구 |
|---|---|
| 제목 | "변경 신청" (PRD에 없음 → 확정 1) |
| 신청 요금제 요약 | 요금제 이름, 매달 내는 돈 |
| 이름 플레이스홀더 | "이름" (텍스트, 1~20자) |
| 휴대폰 플레이스홀더 | "010-0000-0000" (숫자 키패드, 숫자 11자리 입력 시 하이픈 자동 삽입) |
| 동의 체크박스 | "[필수] 개인정보 수집·이용에 동의합니다" + 오른쪽 "보기" 링크 |
| 바텀시트 내용 | 수집 항목(이름, 휴대폰 번호) · 이용 목적(요금제 변경 신청 처리) · 보관 기간 "신청 처리 완료 후 파기" (자리표시 문구, PRD 미정 → 확정 2) |
| 신청 버튼 (하단 고정) | "신청 완료하기" (기본 비활성) |
| 상단 버튼 | "취소" |
| 큰 제목 (make-export 결정, PRD에 없음) | "신청 정보를 입력해 주세요" |
| 입력 라벨 (make-export 결정, PRD에 없음) | "이름" / "휴대폰 번호" (화면에 표시) |
| 요약 행 라벨 (make-export 결정, PRD에 없음) | "선택한 요금제" / "매달 내는 돈" |
| 바텀시트 제목 (make-export 결정, PRD에 없음) | "개인정보 수집·이용 동의" |
| 바텀시트 버튼 (make-export 결정, PRD에 없음) | "확인" (시트 닫기, 체크 상태 그대로) |

오류 문구 (PRD 4-4 표 원문)

| 상황 | 판정 시점 | 안내 문구 | 처리 |
|---|---|---|---|
| 이름 빈 값 | 이름 필드에서 포커스가 빠질 때 | "이름을 입력해 주세요." | 필드 아래 문구 표시, 버튼 비활성 유지 |
| 이름 20자 초과 | 입력 중 | "이름은 20자까지 입력할 수 있어요." | 21번째 글자부터 입력 막음 |
| 휴대폰 번호 형식 오류 (010으로 시작하는 숫자 11자리가 아님) | 휴대폰 필드에서 포커스가 빠질 때 | "휴대폰 번호 11자리를 정확히 입력해 주세요." | 필드 아래 문구 표시, 버튼 비활성 유지 |
| 저장 실패 (네트워크·서버 오류) | 신청 버튼 탭 후 | "신청을 완료하지 못했어요. 잠시 후 다시 시도해 주세요." | 입력값 유지, 버튼 다시 활성 |

동작·규칙
- 두 필드 기본 빈 값, 체크박스 기본 해제.
- 활성 조건: 이름 1자 이상 AND 휴대폰 번호 형식 통과 AND 동의 체크.
- 탭 → 버튼 비활성+로딩(중복 제출 방지) → `Subscription`을 `status = received`로 저장 → 성공 시 신청 완료.
- 바텀시트를 닫아도 체크 상태는 바뀌지 않는다.
- "취소" → 입력값 지우고 요금제 상세.

### 신청 완료 (PRD 4-5)

| 구분 | 문구 |
